# Personal site redesign — design spec

Date: 2026-10-03 · Site: https://omargaly.github.io (GitHub Pages, static only)

## 1. Goal and audience
A modern developer's personal site to share with friends and fellow developers and to show off a little. Not a CV and not aimed at recruiters. It must look current and polished, load fast and work on a phone.

Out of scope:
- Any detail about Kwaaka's internals, POS systems or the internal AI project (NDA).
- A backend of any kind. Everything is static HTML/CSS/JS; external data comes only from public APIs called from the browser.
- Project showcase content. There is nothing to show yet; the section is a placeholder driven by data.

## 3. Languages
- Default EN, plus RU and KZ. Switcher EN / RU / KZ in the header; choice remembered in `localStorage` (wrapped in try/catch).
- Texts live in `i18n/en.json`, `i18n/ru.json`, `i18n/kz.json`. A dependency-free Node script `build.mjs` renders `/`, `/ru/`, `/kz/` from templates and the JSON files. Generated pages are committed (GitHub Pages serves them as-is). Each language has its own URL, `<html lang>`, `hreflang` links and Open Graph tags.
- KZ is a draft translation by Claude, shown with a visible **beta** badge until a native speaker proofreads it. Removing the badge is a one-line change.

## 4. Architecture
Vanilla HTML, CSS and ES modules. No framework, no runtime CDN. Fonts (Inter and JetBrains Mono, Latin + Cyrillic + Kazakh letters) self-hosted as woff2 subsets.

```
index.html, ru/, kz/          generated by build.mjs
src/templates/                page templates
src/data/*.json               experience, education, stack, projects, lab tools
i18n/{en,ru,kz}.json          UI strings and copy
assets/css/                   tokens.css, base.css, components.css
assets/js/                    theme, i18n switcher, reveal animations, terminal, duration
assets/img/, assets/fonts/
lab/                          index + one page per tool, shared layout
lab/lib/                      pure logic modules (no DOM), unit-tested
tests/                        node:test suites
build.mjs
```

Content (experience, projects, stack, lab tool list) is data, so adding a project is one JSON entry, not a markup change.

## 5. Home page
Hero (photo, name, title, tagline, socials) → About → Experience and Education → Stack → Projects (placeholder "coming soon", data-driven) → Lab teaser → Footer.

Visual: dark by default, light theme toggle that also respects `prefers-color-scheme`; colours defined as CSS tokens. Bento-style grid, large typography, subtle scroll-reveal animations disabled under `prefers-reduced-motion`. Responsive from 360px wide. Keyboard accessible, visible focus styles, sufficient contrast.

## 6. Terminal easter egg
Opens with the `` ` `` key or the Konami code, and via a small discreet button for touch devices. Commands: `help`, `whoami`, `stack`, `now`, `contact`, `lab`, `theme`, `lang`, `clear`, plus hidden commands that reveal CTF flags. Output is localised where practical. Closes with Esc.

## 7. /lab
Index page and separate tool pages sharing one layout. All client-side; no input is sent anywhere. Pure logic lives in `lab/lib/` and is tested.

1. **GitHub Pulse** — public GitHub API (activity, languages, repos) drawn as hand-written SVG/canvas. Results cached in `localStorage` with a TTL. On API error or rate limit it shows the last cache or a friendly empty state.
2. **Swiss-army knife** — JWT decoder, Base64, UUID generator, timestamp converter.
3. **JSON → Go struct** (and back), with json tags.
4. **Crypto / CTF kit** — CyberChef-lite operation chains (Base64, hex, ROT13, XOR, URL), classical ciphers (Caesar with all-25-shift brute force, Vigenère, Atbash, ROT13, Morse) with a frequency-analysis cracker, hashes via Web Crypto (SHA family, HMAC), an encoding detector.
5. **Mini-CTF** — three or four hidden flags across the site (page source, console, terminal), a small scoreboard in `localStorage`.

If time is tight, tools 1–4 ship first and 5 follows.

## 8. Images and performance
Avatar as AVIF/WebP with fallback and a 2x variant; icons inline SVG; backgrounds pure CSS; an `og-image` for link previews; favicon. Remove `fslightbox.js`, the PNG icons, `project.png` and the heroku typing SVG. Targets: under about 150 KB for the home page excluding fonts, Lighthouse 95+ on mobile.

Repository hygiene: stop tracking `.idea/` (add to `.gitignore`).

## 9. Error handling
- `localStorage`/`fetch` failures never break rendering.
- Every lab tool shows clear inline errors for invalid input (bad JSON, bad JWT, invalid cron).
- If JS is disabled, the home page content is still fully readable (progressive enhancement; the switcher and terminal need JS).

## 10. Testing
- `node:test` for `lab/lib/*` (ciphers, json2go, jwt, hash helpers, duration) and `build.mjs` output (all three languages render, no missing keys across the i18n files).
- Manual check in Chrome: widths 360 / 768 / 1280, both themes, all three languages, terminal, every lab tool, link check.
- Lighthouse run before merging each phase.

## 11. Delivery phases
- **Phase 1:** structure, design system, i18n and build script, home page, terminal, image optimisation, cleanup.
- **Phase 2:** `/lab` — shared layout, then tools one by one (Pulse, Swiss-army knife, JSON→Go, Crypto/CTF kit, mini-CTF).
